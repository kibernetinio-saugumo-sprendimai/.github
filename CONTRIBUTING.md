# Contributing

1. Open an issue for material architecture or policy changes before implementation.
2. Create a focused branch and keep unrelated changes separate.
3. Add or update tests and documentation for changed behavior.
4. Run the repository's documented verification commands locally.
5. Open a pull request using the template and disclose security, compatibility and migration impact.

Pull requests must not contain credentials, private keys, personal data, generated runtime data or claims of approval that lack independently verifiable evidence. Security-sensitive changes require review by the designated code owner. Do not merge your own security-sensitive pull request without a second reviewer.
