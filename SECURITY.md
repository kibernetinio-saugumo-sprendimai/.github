# Security policy

## Reporting a vulnerability

Do not open a public issue for vulnerabilities, exposed credentials or personal data. Use GitHub's private vulnerability reporting feature in the affected repository. If that feature is unavailable, contact the organization owners privately and share only the minimum reproduction data.

Include the affected repository and revision, impact, safe reproduction steps and suggested remediation. Do not access data that is not yours, disrupt production services or publish details before a coordinated fix is available.

## Supported versions

Only the default branch and explicitly signed releases are supported. Archived repositories and unsigned candidate artifacts are reference material, not supported releases.

## Response targets

The project aims to acknowledge complete reports within five business days. Timing for remediation and disclosure depends on severity and affected users.
